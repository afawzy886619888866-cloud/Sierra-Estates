# Sierra Estates Data Architecture

## Primary Database: Firebase Firestore

### `listings` Collection

Properties available for sale or rent.

- `id` (string)
- `title` (string)
- `price` (number)
- `location` (string)
- `compound` (string, optional)
- `bedrooms` (number)
- `status` (active | sold | archived)
- `syncedToPF` (boolean)
- `aiScore` (number)

### `leads` Collection

Inquiries coming from Web, WhatsApp, or Property Finder.

- `id` (string)
- `name` (string)
- `phone` (string)
- `source` (property_finder | whatsapp | web)
- `status` (pending_review | active | warm | hot | cold)
- `stage` (new_inquiry → closed_won)
- `neuralMatchScore` (number)

### `interactions` Collection

Message logs between leads and AI agents.

- `leadId` (reference)
- `direction` (inbound | outbound)
- `channel` (whatsapp | email)
- `content` (string)
- `timestamp` (Date)

## Vector Database / AI Cache

- Text embeddings generated by `memory-engine` stored in Cloud Storage or a dedicated vector database (Pinecone/Weaviate) for semantic search over `listings`.

## Storage

- **Firebase Storage**: Hosting high-resolution images, floor plans, and generated PDF brochures.
