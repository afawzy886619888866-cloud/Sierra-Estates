# Supabase SSR Clients (`utils/supabase`)

Standard `@supabase/ssr` integration (cookie-based sessions) for the Next.js 16
App Router. Wired to `NEXT_PUBLIC_SUPABASE_URL` and
`NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` from `.env.local`.

| File | Purpose |
| --- | --- |
| `server.ts` | Cookie-bound server client for Server Components / Route Handlers that must run **under RLS** with the signed-in user's session. |
| `client.ts` | Cookie-backed browser client (`createBrowserClient`) whose session is visible to the server, unlike the legacy localStorage clients. |
| `middleware.ts` | Session refresh helper invoked from the proxy boundary (`proxy.ts`); renews auth cookies and forwards them on the final response. |

## Relationship to the existing clients

- `lib/supabaseClient.ts` and `lib/supabase.ts` (via `@sierra-estates/db`) are
  **retained and unchanged** — they use supabase-js with localStorage/session
  persistence and remain valid for the flows that already use them.
- `getSupabaseAdmin()` (service-role) **bypasses RLS**; prefer `createClient`
  from `server.ts` whenever the caller should be row-level-security scoped.
- The proxy refresh is **fail-soft**: if the public env vars are missing,
  `proxy.ts` skips the Supabase step entirely, so CORS/gating behavior is
  unaffected by a partial environment.

## Adding the wizard's `todos` demo (optional)

The Supabase quickstart demo page queries a `todos` table, which does not
exist in the current project. If you want it, create the table first, then add
a page using `createClient` from `server.ts`:

```sql
create table public.todos (
  id bigint generated by default as identity primary key,
  name text not null
);
alter table public.todos enable row level security;
```
